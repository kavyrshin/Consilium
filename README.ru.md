# Consilium

[![tests](https://github.com/kavyrshin/Consilium/actions/workflows/ci.yml/badge.svg)](https://github.com/kavyrshin/Consilium/actions/workflows/ci.yml) [![release](https://img.shields.io/github/v/release/kavyrshin/Consilium)](https://github.com/kavyrshin/Consilium/releases/latest) [![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

[English version](README.md)

Скилл для **Claude Code** и **Codex**, который проводит *консилиум*: несколько независимых моделей ревьюят один и тот же технический вопрос, два арбитра сводят обзоры в **черновик** решения, и только после вашего подтверждения исполнитель вносит изменения, а проверяющие их проверяют. Финальный арбитр — всегда человек; ни одна модель ничего не решает.

Одна папка, один `SKILL.md`, обычные bash-скрипты. Всё, что создаёт процесс, — обычный markdown в вашем проекте: его можно читать, сравнивать и хранить.

```
brief.md ─┬─► обзор хоста (агент, с которым вы разговариваете)  ┐
          ├─► ревьюер 2 (внешний CLI, параллельно)             ├─► decision.md ─► вы подтверждаете
          └─► ревьюер 3 (внешний CLI, параллельно)             ┘   (ЧЕРНОВИК, два арбитра)
                                                                        │  только после подтверждения
                                   исполнитель ─► проверяющие ─► исполнитель правит ─► вы смотрите дифф
```

## Зачем

Одна модель, ревьюящая собственную идею, склонна с ней соглашаться. Независимые обзоры от разных моделей находят разное, а требование сначала записать факты, допущения, риски и рекомендацию и только потом читать чужое не даёт им подстраиваться. Арбитры обязаны явно фиксировать разногласия, а не усреднять их, и о том, кто не ответил, пишет скрипт, а не модель.

## Требования

- `bash` 3.2+ (штатный macOS подходит), `git`, `python3`; Node.js 18+ — только для необязательного ридера
- Хотя бы один CLI-агент в `PATH`. Каждый найденный становится доступным ревьюером, арбитром, проверяющим или исполнителем:

| Адаптер | CLI | Примечание |
| --- | --- | --- |
| `claude` | [Claude Code](https://claude.com/claude-code) (`claude -p`) | |
| `codex` | [Codex CLI](https://github.com/openai/codex) (`codex exec`) | модель берётся из `~/.codex/config.toml` |
| `opencode` | [Open Code](https://opencode.ai) (`opencode run`) | нужен `CM_OPENCODE_MODEL`, см. ниже |
| `deepseek` | DeepSeek Harness (`dsh`) | необязательный, работает, только если найден |
| `mock` | не нужен | пишет текст-заглушку; чтобы попробовать конвейер без моделей |

Свой адаптер: [docs/adapters.md](docs/adapters.md), это файл примерно из 10 строк.

**Хост** — агент, в котором вы запускаете скилл. Свой обзор он пишет сам, поэтому второй раз его не запускают. Если установлен только один CLI, консилиум всё равно работает, с меньшим составом, и решение прямо об этом скажет.

## Установка

Стабильный релиз (рекомендуется):

```bash
git clone --branch v0.1.0 --depth 1 https://github.com/kavyrshin/Consilium.git
cd Consilium
./install.sh                # для каждого агента, у которого есть конфиг-папка (~/.claude, ~/.codex)
```

Последняя версия в разработке:

```bash
git clone https://github.com/kavyrshin/Consilium.git
cd Consilium
./install.sh                # для каждого агента, у которого есть конфиг-папка (~/.claude, ~/.codex)
```

Опции: `--claude`, `--codex`, `--agents` (`~/.agents/skills`), `--dir PATH` (например, `./.claude/skills` для одного проекта), `--symlink` (правите репозиторий — видите изменения сразу), `--force`, `--uninstall`.

Или скопируйте `skills/consilium/` в папку скиллов вашего агента вручную.

## Использование

В агенте:

| Агент | Вызов |
| --- | --- |
| Claude Code | `/consilium Кешировать X в Redis или в памяти процесса?` |
| Codex | `$consilium Кешировать X в Redis или в памяти процесса?` |

Скилл запускается **только по вашей просьбе**: он тратит лимиты моделей и отправляет файлы проекта нескольким провайдерам.

Что происходит:

1. Агент показывает состав (`run-reviewers.sh --plan`) и создаёт `consilium/<дата>-<slug>/`.
2. Собирает факты (только чтение) и заполняет `brief.md`. Пока бриф не заполнен, ревьюеры не запускаются.
3. Внешние ревьюеры стартуют параллельно, в фоне. Агент пишет свой обзор, не читая чужие.
4. Наблюдатель сводит `decision.md`, когда все ответили или отказали. Арбитров двое: первый пишет черновик, второй правит и обязан зафиксировать разногласие.
5. **Вы читаете и подтверждаете черновик.** До этого ничего не реализуется (если вы не сказали иначе сразу).
6. Исполнитель вносит только то, что перечислено в «Разрешённые изменения в коде», в отдельном git worktree; проверяющие независимо проверяют; исполнитель исправляет найденное. Без коммитов и пушей.

Как выглядит папка кейса — в [`examples/`](examples/).

## Настройка

Обычные строки `KEY=VALUE` в `<проект>/.consilium.conf` или `~/.config/consilium/config`. Переменные окружения важнее файла проекта, тот — файла пользователя. Файлы **разбираются, а не исполняются**. Файл проекта считается недоверенным, потому что приходит вместе с любым склонированным репозиторием: в нём можно задать только состав, язык, модели, таймауты и относительную папку кейсов внутри проекта. Настройки, которые подключают код или запускают команды (`CM_ADAPTERS_DIR`, `CM_NOTIFY_CMD`), и пути за пределами проекта принимаются только из окружения или вашего пользовательского конфига; скилл сообщает, что проигнорировал. За основу возьмите [`consilium.example.conf`](skills/consilium/consilium.example.conf).

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `CM_LANG` | `en` | язык документов: `en` или `ru` |
| `CM_HOST` | `claude` | агент, в котором запущен скилл (`claude` / `codex`) |
| `CM_REVIEWERS` | `claude codex opencode deepseek` | внешние ревьюеры; недоступные пропускаются с пояснением |
| `CM_ARBITERS` | `codex claude` | первые два доступных сводят черновик |
| `CM_VERIFIERS` | `codex claude` | проверяют реализацию параллельно |
| `CM_IMPLEMENTERS` | `claude codex opencode` | реализует первый доступный |
| `CM_OUT_DIR` | `consilium` | папка кейсов относительно корня проекта |
| `CM_OPENCODE_MODEL(S)` | не задан | **обязателен**, чтобы включить Open Code: в headless-режиме у `opencode` нет модели по умолчанию |
| `CM_CODEX_MODEL`, `CM_CLAUDE_MODEL`, `CM_CLAUDE_EFFORT` | из самого CLI | переопределение модели |
| `CM_*_TIMEOUT` | 30 / 15 / 45 / 45 мин | ревью / решение / проверка / реализация |

Посмотреть, кто запустится и кого пропустят, ничего не запуская:

```bash
bash ~/.claude/skills/consilium/scripts/run-reviewers.sh --plan   # установлен для Claude Code
bash ~/.codex/skills/consilium/scripts/run-reviewers.sh --plan    # установлен для Codex
```

### Языки

По умолчанию английский, русский встроен (`CM_LANG=ru`). Чтобы добавить свой, скопируйте `skills/consilium/lang/en.sh` и `skills/consilium/templates/en/` под своим кодом, переведите значения и задайте `CM_LANG=<код>`. Заголовки разделов — часть контракта (валидатор решения сверяет их точно), поэтому меняйте формулировки, а не механику.

## Ридер

Локальная веб-страница для чтения кейсов: все кейсы в боковой панели, документы в порядке процесса (бриф, обзоры, решение, реализация), обновление на лету, пока ревьюеры и арбитры пишут. Нужен Node.js 18+.

```bash
bash ~/.claude/skills/consilium/scripts/reader.sh --open     # http://localhost:4600
```

Запускайте из корня проекта (`~/.codex/...`, если ставили для Codex). `--port N` меняет порт. Ридер слушает только `127.0.0.1`, отклоняет чужие заголовки `Host`, отдаёт только markdown кейсов и рендерит документы очищенными, под строгой Content-Security-Policy: их пишут модели, которые могли прочитать враждебный контент.

### Показать через ngrok

Чтобы показать кейс кому-то за пределами вашей машины, запустите ридер в публичном режиме и поставьте перед ним туннель:

```bash
bash ~/.claude/skills/consilium/scripts/reader.sh --public   # напечатает логин и одноразовый пароль
ngrok http 4600                                              # во втором терминале
```

Отправьте адрес `https://….ngrok-free.app` и пароль отдельными сообщениями. В публичном режиме пароль нужен на каждый запрос (свой можно задать через `CM_READER_PASSWORD`, от 12 символов), а локальные пути скрыты.

**Подумайте, прежде чем делиться:** любой, у кого есть адрес и пароль, прочтёт все кейсы в папке, а в кейсах цитируется ваш код. Когда закончите, остановите оба процесса (Ctrl+C). Для более сильной защиты ngrok может требовать вход через Google или GitHub перед туннелем — через [traffic policy](https://ngrok.com/docs/traffic-policy/).

## Данные и приватность

**Прочтите это, прежде чем запускать на закрытом коде.** Каждый ревьюер, арбитр, проверяющий и исполнитель — это CLI-агент, который читает файлы вашего проекта и отправляет прочитанное своему провайдеру. Состав из четырёх — до четырёх провайдеров, увидевших ваш код. У бесплатных и «contributor»-тарифов условия по данным могут отличаться от платных, проверяйте каждый. Управляйте составом через `CM_REVIEWERS=` и `--plan`.

## Модель безопасности

- Ревьюерам, арбитрам и проверяющим велено не менять код; файлы меняет только исполнитель, только в выданном ему worktree и только то, что разрешает подтверждённое решение. Он не коммитит, не пушит и не переключает ветки.
- Codex работает с `--sandbox workspace-write`; Claude в headless-режиме — с явным списком инструментов (чтение/запись/правка/поиск, а shell — только у проверяющих и исполнителя). Проверяющие и исполнитель могут выполнять команды: дайте им worktree, а не единственную копию.
- Арбитры пишут в файл-кандидат, а не в `decision.md`; кандидат публикуется только после проверки структуры, а живой файл побайтно восстанавливается, если арбитр его тронул.
- Пометку о неполном составе пишет скрипт по фактам на диске, а не модель.
- Решение — всегда черновик с плашкой; подтверждает его человек.

## Структура

```
skills/consilium/
  SKILL.md                 сам скилл (Claude Code и Codex читают один и тот же файл)
  agents/openai.yaml       метаданные Codex: без автозапуска
  scripts/                 init-case, run-reviewers, run-reviewer, watch-and-decide,
                           write-decision, implement, verify, lib.sh, mock-agent
  scripts/adapters/        по файлу на каждый CLI-агент
  reader/                  локальный веб-ридер (запускается через reader.sh)
  lang/  templates/        формулировки по языкам
  consilium.example.conf
install.sh   tests/   docs/   examples/
```

## Тесты

```bash
bash tests/run.sh
```

Проверка синтаксиса, `shellcheck` (если установлен) и сквозные прогоны на mock-адаптере: конвейер на обоих языках, фолбэки арбитров, защита живого файла, таймауты, реализация/проверка, безопасный разбор конфига. Без сети и без вызовов моделей.

## Статус

Скрипты и конвейер на mock-адаптере протестированы; адаптеры `claude`, `codex`, `opencode`, `deepseek` оборачивают настоящие CLI, флаги которых меняются между версиями, поэтому сначала запустите `--plan` и попробуйте маленький вопрос. Сообщения о несовместимости с версиями CLI приветствуются.
